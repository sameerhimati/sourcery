Method

How the numbers on the results page were made: what varies between arms, the rubrics the judges scored on, what every provider was asked for, and what one run cannot tell you.

What varies

One question goes to all eight providers. Each returns up to 8 results. Nothing else differs between arms: same prompt, same judges, same number of results requested, caching off. Of the eight arms, six finished inside a single day. Tavily and Bright Data ran into their own rate limits and finished in the early hours of the next morning, and that is the one respect in which the arms were not treated identically: a page that changed overnight would have been seen differently by those two.

The settings live in one file, core/controls.ts, and every stage imports from it, so there is only ever one value of anything for a stage to read. Every provider was set to the highest-quality tier it offers; where a depth or content knob existed it was turned up.

The two rubrics

Both ask the same question at two scopes, on the same 0–3 scale, and every score comes with a written definition. Two models can agree on what a 2 means; a bare number on a wide scale is something each one invents its own version of.

Page rating — does this page help?

One question, one page. The judge is never told which provider returned it, never shown an answer, and never asked to write one.

0
not relevant
does not address the question
1
marginal
on the topic, but would not help answer it
2
relevant
contains part of the answer, or usable evidence toward it
3
highly relevant
answers the question directly

Set rating — could someone answer from these alone?

The headline. A per-page average cannot answer this: eight pages each holding a third of the answer and eight holding nothing average out the same.

0
nothing
no source here addresses the question
1
on topic only
about the right subject, but reading all of it would not answer the question
2

part of the answer is here; the rest would need another search
3
answerable

Both prompts are in core/controls.ts in full. The set prompt replaced an earlier one partway through the run, which graded whether sources looked good: fresh, authoritative, cleanly extracted. On a question with no answer anywhere it returned a passing score while the page judge rated every page 0 or 1. The sources were good, they just could not answer.

Pooling

Providers overlap heavily. Every page from every arm is collapsed into one pool keyed by normalized URL and graded once; that rating counts for each provider that returned it. 66.8% of the 7,496 pages came from exactly one provider and 24 came from all eight.

Pooling blinds the judge structurally: a page is detached from whoever returned it before grading, so there is no provider name to be swayed by. The cost is that where several arms returned the same URL, the longest extraction anyone returned is what gets graded, so extraction quality is averaged away on those pages.

The statistics, in words

Confidence interval

Where the real value probably sits, given that 204 questions is a sample. Two overlapping intervals mean the order between those providers is not a finding.

Variance shares

How much of everything that varies is explained by each thing that could explain it. The provider explains 23.1%; which judge you picked explains 2.2%.

Kappa

Agreement between two judges after subtracting the agreement you would get by chance. These three run 0.51 to 0.55: they agree on the order and argue about the decimals.

Sign test

Comparing two providers across the same small set of questions by counting wins, then asking how often a split that lopsided would happen by luck. Used on the 12 unanswerable questions, where eight providers cannot be ranked but two can be compared.

What this cannot tell you

Who extracts a page best

Each source gets a 1600-character slice, which is what an agent with a real context budget would allow. A larger slice would let the providers that return whole documents show more of what they extract, and it could reorder the bottom of the table. Pooling costs the same measurement a second way: on the 33% of pages that several arms returned, the longest extraction anyone returned is the one that got graded. Measuring extraction properly means holding the URLs fixed and varying only the extractor, and that run has not happened.

What your agent will answer

Nothing here grades an answer, on purpose. An answer-graded benchmark measures that, bearing in mind such a number also grades your model.

How any of this behaves at scale

Every arm was run once, at whatever concurrency it tolerated, so nothing here measures throughput, quota behaviour, or what any of these costs at volume. What this run did collide with is written up in notes from the run: a provider that throttles at one request, a plan that ran out mid-way, a day that ate most of a month's credits. Those are things that happened once; none of them is a measurement.

Whether the questions look like yours

204 questions written to probe retrieval, not collected from real traffic: 96 ordinary, 96 deliberately hard, 12 with no answer at all. I wrote all of them, so whatever I find interesting is in the sample and whatever I did not think to ask is not. Frozen and public, so you can judge the resemblance. The harness exists so you can run your own instead.

Whether tomorrow would come out the same

This is one run, fetched 17–18 August 2026. Every provider is a moving target: indexes change, tiers change, and a model behind one of these can be swapped without telling you. Nothing here is measured twice, so none of these numbers carries an estimate of how much it would move on a re-run. The confidence intervals describe sampling across questions within this one run, which is a narrower claim than it looks.

Whether the judges are right

Three large language models grade every page, and they agree with each other well enough to trust the ranking, kappa 0.51 to 0.55, moderate on a four-point scale. That is agreement among themselves, not agreement with a person. They were calibrated against human-settled pairs before the run, but three models trained on overlapping text can share a blind spot and agree anyway, and the 12 unanswerable questions show one: a plausible near-miss fools some of them.

How fast any of them are for you

The table has a median latency column, so timing is measured, but it is measured from one machine on one network over two days, and a provider that is quick from my connection may not be quick from your region. Take the ordering seriously and the absolute numbers loosely.

Every rating is published with the sentence the judge wrote to justify it. Any number here traces back to the verdict that produced it.
